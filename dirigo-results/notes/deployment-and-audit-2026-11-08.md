## test_hip_ordinal fixed (2026-11-08) — the suite is now fully green

Cause: the split-list case in `serve/test_server.py` read the HOST's KFD topology. `child_env({"gpu":[1,0]})` goes
through `ordered_gpus()`, which deliberately moves built-in graphics first (#1576), so on any box with an integrated
Radeon in `HIP_IGPU_ARCHS` the list comes back `0,1` while the assertion wanted `1,0` — red on AMD machines, green on
CI where no AMD card can be probed. Not a carry defect: it fails on the unmodified tag too.

Fix (test only, 20 lines): stub `hip_gpu_archs`/`hip_speed_scores` for the "cannot measure" case, and pin the
deliberate reorder plus the documented `"gpu_order": "as_given"` escape hatch through `ordered_gpus()`'s existing
test seam. Committed as `db0a46759` on `release/0.2.12`; the clean-room tree carries the same file (tree hash still
identical). Suite after: **1,535 tests in 611.4 s, OK (skipped=17), 0 failures**.

Submitted upstream as **#5602** (`[Engine] tests: test_hip_ordinal fails on any machine with an integrated Radeon`),
with the A/B: unmodified tag FAILED, fixed class 11/11 OK.
